# API contract — `/api/v1` (proposed)

All API data is JSON; FastAPI/Pydantic validates input and output. These are interface contracts for parallel development, not deployed endpoints.

## Core contracts

### `POST /profiles/extract`

Request: `{"text":"I am a 24-year-old farmer in Maharashtra", "locale":"en-IN"}`

Response: `{"facts":{"age":24,"state_code":"MH","occupation":"farmer","land_area_acres":null},"unknown_fields":["land_area_acres"],"needs_review":true}`

Returns `422` on invalid input or `503` if model unavailable; allows manual intake fallback. Field values are not yet verified until reviewed.

### `POST /matches`

Request: `{"session_id":"UUID", "facts":{"age":24,"state_code":"MH","occupation":"farmer","land_area_acres":1.5}, "limit":5}`

Response (abridged):

```json
{
  "run_id": "UUID",
  "results": [
    {
      "scheme_id": "UUID",
      "scheme_name": "Example Scheme",
      "scheme_version_id": "UUID",
      "status": "needs_information",
      "relevance_score": 0.84,
      "matched_rules": [{"rule_key":"state","result":"pass","source_id":"UUID"}],
      "failed_rules": [],
      "unknown_rules": [{"rule_key":"registration","result":"unknown","required_field":"land_registration"}],
      "last_verified_at": "2026-09-20T00:00:00Z",
      "official_source_urls": ["https://example.gov.in/example"]
    }
  ]
}
```

`Example Scheme` and URL above are contract placeholders. Never seed or display placeholder links in production.

### `POST /questions/next`

Request: `{"session_id":"UUID", "run_id":"UUID"}`

Response: `{"field":"land_registration","question":"Is the land registered to your family?","answer_type":"single_choice","options":["yes","no","not_sure"],"reason":"A leading scheme has an unresolved ownership condition"}`. If no blocking question, return `question: null`.

### `POST /profiles/answers`

Request: `{"session_id":"UUID","field":"land_registration","value":"not_sure"}`; response includes updated facts and `requires_rematch: true`.

### `GET /schemes`

Query: `?q=farmer&state_code=MH&category=agriculture&limit=20`; returns only published/verified scheme summaries, source metadata and paging cursor.

### `GET /schemes/{scheme_id}`

Returns benefit summary, eligibility rule explanations, exclusions, source links, documents, application window status and last verification date.

### `GET /guidance/{scheme_id}?session_id={uuid}`

Returns ordered steps, verified document requirements with `present|missing|unknown`, official URL, and any unresolved preconditions. No generated application submission.

### Optional `POST /saved` / `GET /saved`

Requires a valid session; guest saves expire with the session.

### Admin `POST /admin/schemes` and `POST /admin/schemes/{id}/publish`

Protected role, validation, provenance, audit logs, and reviewer approval. CLI seeding is acceptable MVP fallback if admin UI isn't ready.

## Shared enums

- Verdict: `all_checked_conditions_met | needs_information | not_eligible | manual_review`.
- Rule result: `pass | fail | unknown | manual_review`.
- Record review: `draft | verified | stale | rejected`.
- Error payload: `{"error":{"code":"VALIDATION_ERROR","message":"...","request_id":"..."}}`.

## Integration rules

- Frontend renders `relevance_score` only for internal ordering; **do not display as eligibility percentage**.
- API never trusts model output directly; check JSON schema and allowable fields.
- All result labels, sources and current application status come from backend.
- OpenAPI generated by FastAPI; freeze a sample response fixture before frontend integration.
